# Archive 감사와 개선 결과 쉬운 정리

## Executive Summary

- **코드에서 바로 고칠 수 있는 큰 문제는 대부분 개선했습니다.** 반복 빌드, DB 쓰기 차단, 사용자 소유권, 주요 목록 제한, 차트·표 접근성은 개발 소스와 개발 서버에 반영됐습니다.
- **운영 환경이 필요한 검증은 남아 있습니다.** 실제 HTTPS cookie, 최신 Tomcat, 격리 DB 쓰기 테스트와 인증 내부 화면 40개 확인은 아직 완료되지 않았습니다.
- **Git 원격 저장소만으로 현재 개발 서버를 완전히 복구할 수는 없습니다.** 로컬 `develop`이 원격보다 7커밋 앞서고 작업 트리 변경도 남아 있습니다.
- 이 문서에서 나눈 46개 조치 항목은 `완료 29개`, `일부 완료 10개`, `남음 7개`입니다. 개수는 위험 점수가 아니라 아래 표를 쉽게 세기 위한 분류입니다.

| 느린 요청 원인 추적 | request ID, pool 대기, 읽은 행, 파일 scan 정보가 부족 | 기존 요청 시간·SQL 횟수·SQL 시간·최대 SQL 시간과 slow log는 유지 | 느린지는 알지만 어디서 기다렸는지는 완전히 모름 | 일부 완료 |
| 프론트 자원 | 폰트 4종 1.68MB, versioned asset도 cache 5분 | 모바일·모션 감소·숨은 탭에서 배경 애니메이션 중단은 확인, cache·font 축소는 미적용 | 움직임 낭비는 막았지만 파일 다운로드 양은 더 줄일 수 있음 | 일부 완료 |

## 검증 근거와 주의사항

- 최종 clean build 2회 성공, 두 WAR는 바이트 단위로 동일했습니다.
- 전체 테스트 408개, JspC 38 source/63 class, JavaScript 27개가 모두 통과했습니다.
- 최종 WAR는 개발 Tomcat에만 배포했고 운영 PID·WAR hash·8080 응답은 유지됐습니다.
- 공개 로그인 화면은 5개 크기에서 console 오류와 전체 페이지 가로 넘침이 0이었습니다.
- 인증 내부 화면 40개, 격리 DB 쓰기 E2E, 실제 운영 HTTPS cookie, Tomcat 업그레이드는 아직 완료되지 않았습니다.
- 5단계는 별도 remediation 보고서가 없어 4단계·6단계 조치 결과와 현재 소스 계약을 함께 대조해 상태를 표시했습니다.
